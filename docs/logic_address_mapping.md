# Logic file — Part B: Linking TIN → NPI → address, and specialty (C5)

**Problem (PS):** rates come with an NPI and a TIN but no address or specialty. One TIN can have many addresses and
one NPI can practise at many addresses. About 80% of NPPES addresses are stale, so NPPES alone is not enough.
Running an address tool on NPPES is a baseline, not a solution.

**Our approach in one line:** collect candidate addresses from **independent** sources, **standardize and validate**
them, use the **TIN–NPI structure of the rate file itself** as corroboration, and grade each address
**VERIFIED / PROBABLE / UNVERIFIED** with the evidence written next to it.

Every number in the results section comes from `data/stage5/c5_report.txt` (generated by the run).

---

## 1. Sources and what each adds

| Source | What it adds | Why it's independent |
|---|---|---|
| **The rate file** (TIN → NPIs) | which NPIs bill under which TIN: the backbone of the link | it's the contract data itself |
| **NPPES API** (primary LOCATION + secondary practice locations) | the provider's self-reported practice sites; taxonomy; **last-updated date** (a staleness signal) | maintained by the provider |
| **CMS Doctors & Clinicians (DAC)**, refreshed monthly (dataset modified 2026-10-02) | practice addresses from **Medicare enrolment** (PECOS), with the **group name** per address | a different system with its own verification, updated monthly |
| **US Census geocoder** | standardizes every address to one form (e.g. `1818 VERDUGO BLVD` → `1818 N VERDUGO RD`); confirms it **exists**; gives county and coordinates | an authoritative address reference |
| NPPES MAILING address | **not used**: a billing or mail address, not a place where care is given | — |

**Considered, not used:** Health Net's FHIR provider directory (behind a login on Centene's developer portal); Health
Net's public directory JSON (Medi-Cal only, not commercial); HiLabs MCheck/R3 (not available to us; it would be a drop-in
replacement for the Census standardization step).

## 2. Linking rules

1. **Candidates per (NPI, TIN):** all NPPES practice locations and DAC addresses of that NPI. TIN-only contracts (NPI "0")
   borrow the candidate addresses of the other NPIs on the same TIN.
2. **Same place = same building:** compare the standardized street + city + ZIP5 (suite kept for display only). So
   "STE 200" vs "SUITE 200" or "BLVD" vs "BOULEVARD" don't create false new addresses.
3. **Evidence for each (NPI, TIN, address):**
   - `n_independent_sources`: NPPES and DAC agree on the building (counts 2)
   - `tin_corroboration`: **another NPI billing under the same TIN practises at this address.** This is the TIN → address link:
     a TIN's addresses are where its NPIs practise, and an address shared inside the TIN is a confirmed site of that TIN
   - `dac_name_match`: the DAC group name at this address shares ≥ 50% of its name tokens with the TIN's business name
     in the rate file. It links the address to *this* TIN when the NPI works for several groups
   - `nppes_current`: NPPES record updated within 24 months (config `address.nppes_fresh_months`)
   - `geocoded`: the Census geocoder matched the address (it exists)
4. **Tiers:**

| Tier | Rule | Meaning |
|---|---|---|
| **VERIFIED** | geocoded **and** (2 independent sources agree **or** 1 source + TIN corroboration **or** 1 source + DAC group-name match) | confirmed by two separate pieces of evidence |
| **PROBABLE** | geocoded **and** one *current* source (DAC, or NPPES updated within 24 months) | likely, but only one current source |
| **UNVERIFIED** | everything else (e.g. only a stale NPPES record, or the address doesn't geocode) | kept and labelled, never silently dropped |
| NONE | no candidate address at all | reported |

5. **Many addresses (one-to-many, as the PS requires):** a pair keeps **every** VERIFIED and PROBABLE address. Ranking
   inside a pair = tier, then evidence points (DAC +2, TIN corroboration +2, NPPES location +1, secondary +1, name
   match +1, current +1, geocoded +1, in CA +1). `is_best` marks the top one.
6. **Conflicts:**
   - NPPES and DAC disagree → both kept as separate candidates; the one with more evidence ranks first. Neither is deleted.
   - An address outside CA → kept, flagged `in_state = False`. It ranks lower because it gets no in-state point (labs often bill from another state).
   - An NPI under several TINs → linked separately per TIN; the DAC group-name match decides which site belongs to which TIN.

## 3. Specialty (needed for the rate file)
Rules, first match wins, with `specialty_source` recorded:
1. NPI's primary NPPES taxonomy in the HiLabs Taxonomy-Spec Xwalk → `NPPES_PRIMARY`
2. a secondary taxonomy in the Xwalk → `NPPES_SECONDARY`
3. a facility taxonomy in the NUCC-verified facility map (config `specialty.facility_taxonomy_map`, e.g. Ambulatory
   Surgical 261QA1903X → 045; Urgent Care 261QU0200X → 080; Skilled Nursing 314000000X → 046) → `FACILITY_MAP`
4. from the HiLabs codes the NPI is priced on: the specialty whose weighted code list they cover most, **only if it
   beats the runner-up by 1.5×** → `CODE_PROFILE`
5. otherwise `Unmapped (<NUCC description>)` (e.g. "Unmapped (General Acute Care Hospital)"): kept, not dropped.

Why: the HiLabs crosswalk covers individual taxonomies only. In a 300-NPI registry sample, 98% of Type 1 NPIs mapped
but only ~51% of Type 2 (`data/stage2/npi_taxonomy_sample.csv`). Steps 3–5 close that gap without inventing specialties.

## 4. Organizations: a second independent source
**Finding:** 82% of the NPIs in the PPO file are organizations (NPPES: 3,054 Type 2, 672 Type 1), and CMS DAC lists only individuals.
On the first run only 13.3% of NPIs reached VERIFIED, because most organizations had just one source.

**Fix: add sources, not loosen rules.** CMS facility registries (California rows), each confirming an address only when it is the
**same building and shares a significant name word** (surgery centres: the **same NPI in the same ZIP**):

| Registry (CMS provider-data) | CA rows | Confirms |
|---|---|---|
| Hospital General Information | 377 | hospitals |
| Ambulatory Surgical Center Quality – Facility | 654 | surgery centres (by NPI) |
| Medical Equipment Suppliers | 4,463 | DME suppliers |
| Home Health Care Agencies | 3,213 | home health |
| DAC by **group name** | 627 groups matched exactly | group practices (the organization's own Medicare group) |

### Two mistakes caught and fixed (kept here on purpose)
1. **Circular name evidence.** DAC group addresses were *selected* by an exact name match, and the rule then counted that same match again as
   corroboration, producing up to 195 "verified" addresses per pair. Fixed: the name match only counts as evidence for individual DAC rows.
2. **Copying a group's sites to every NPI.** Sutter Bay Medical Foundation has 194 Medicare sites; the first version gave all 194 to each of
   the TIN's 23 organization NPIs (Fremont Urgent Care, Antioch Urgent Care, …) and counted the copies as TIN corroboration. Fixed: a group's
   sites only **confirm** an address the NPI itself reports, and TIN corroboration counts only NPIs' **own** records (NPPES or individual DAC).

## 5. Results (run 2026-10-17, `data/stage5/c5_report.txt`)

| Measure | Value |
|---|---|
| (NPI, TIN) pairs | 3,780 (8 with no address in any source) |
| Distinct candidate addresses / confirmed to exist by the Census geocoder | 4,275 / 3,976 (93.0%) |
| **NPIs with ≥ 1 VERIFIED address** | **1,639 of 3,734 (43.9%)** (verified or probable: 58.0%) |
| **TINs with ≥ 1 VERIFIED address** | **1,170 of 2,888 (40.5%)** (verified or probable: 55.9%) |
| Best address per pair | VERIFIED 1,655 · PROBABLE 538 · UNVERIFIED 1,579 · NONE 8 |
| How VERIFIED best addresses were confirmed | 2+ independent sources 1,528 · TIN corroboration 124 · DAC name match 3 |
| Registry confirmations on best addresses | hospital 285+ · DME 204+ · ASC 170+ · home health 36+ (some match two) · DAC group 834 |
| One-to-many | 378 TINs and 317 NPIs have more than one VERIFIED/PROBABLE address (max 110: a behavioral-health group that registers 110 practice sites in NPPES) |

**Why NPPES alone is not enough (evidence from this run):**
- **2,620 of 3,726 NPPES records (70%) were last updated more than 24 months ago.** This matches the PS warning that ~80% of NPPES addresses are stale.
- Of the NPPES primary locations, **1,675 stayed UNVERIFIED** (no second source agrees), 490 are only PROBABLE, and 1,602 are VERIFIED.
- For **309** pairs the best address is **not** the NPPES primary location, and for 122 of them a different address clearly outranks it (higher tier).

**Limits (honest):**
- Individuals not enrolled in Medicare (not in DAC) and organizations outside the four registries can only be PROBABLE at best.
- Hospitals have no HiLabs specialty ("Unmapped (General Acute Care Hospital)", 226 NPIs).
- Building-level matching treats two practices in the same building as the same address; suites are shown but not used for matching.
- The Census geocoder can't match 7% of addresses (PO boxes, new streets); those stay UNVERIFIED rather than being guessed.
